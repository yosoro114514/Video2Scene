# 架构与运行数据

## 组件边界

| 模块 | 输入与职责 | 输出 |
| --- | --- | --- |
| Pi 工作台 | 用户消息、视频、确认与工具调度 | 项目状态、工具调用 |
| Capture / evidence | 原始帧、相机、深度、掩码及哈希 | 与场景版本绑定的证据 |
| Agent scene | 图像先验、几何提议、对象作者与独立 critic | 白模布局、候选资产 |
| Scene state | 已授权的对象／字段变化 | 不可变版本、候选、原子提交 |
| Validation | 支撑、碰撞、边界、相机与证据 | 与候选哈希绑定的报告 |
| Blender backend | 场景与资产 | 实际构建、回渲染、GLB／Blend |
| Editor | 用户数值修改与保存 | 明确用户事件、版本变更请求 |

模型提出动作，宿主验证授权并执行。用户采用白模后，精修继承布局约束。持续调度器持有跨工具调用存活的对象任务；完成一个资产包后可以补入下一件。保存时针对最新场景重新构建与验证，每个场景仅一个保存通道。

`rolling_jobs.py` 管理持久任务与依赖，`resources.py` 管理跨项目共享的模型和 Blender 名额，`job_recovery.py` 与 `process_owner.py` 核对失败凭据和进程身份。默认对象并发 3，可选 1–4；模型默认上限 3、Blender 执行组默认上限 1。作者整个调用保守占用一个 Blender 名额，独立 critic 只占模型名额。[完整工作流](WORKFLOW.md)

## 坐标与版本

场景以米为单位，Y 向上；相机采用 OpenCV 约定。Blender 与场景之间的转换集中在 `capture_evidence/coordinates.py`。观察图像与 ViPE 密集时序通过原始帧号连接，不能把采样序号当作原始帧号。

`contracts_v1` 定义请求／响应与场景结构。`docs/development/contracts/` 保留冻结的 JSON 契约副本，测试会检查副本一致性。

## 文件位置

工作台默认根目录 `outputs/pi_workflow_v1/`：

- `workflow.sqlite`：项目、事件、用户操作和任务索引。
- `projects/<id>/`：源帧、工具输入输出、Pi 会话与精修记录。
- `runtime/`：场景仓库、证据、候选和 Blender 产物。

示例通过 `video2scene demo` 使用独立输出目录和同一套场景仓库／验证器。程序生成的示例图像明确标记为合成，不作为真实视频证据。

## 恢复语义

请求 ID 用于幂等。已保存结果可复用；中断且结果不明的调用保留为待核对状态。主控 Pi 的瞬时连接错误最多重连 5 次，间隔为 2／4／8／16／30 秒。对象 CLI 仅在日志证明尚未执行时处理容量拒绝；有执行或结果不明时不自动重放。显式恢复保留失败历史，重新核对当前授权与进程凭据。运行记录包含绝对路径，跨机器迁移尚未提供自动转换。

## 维护范围

推荐入口为 `demo`、`check` 和 `workbench`。旧 `pipeline` 与场景实验模块用于兼容和几何工具复用；其中部分独立入口需要历史数据。发布包不包含这些原始数据。[完整工作流](../PIPELINE.md)
