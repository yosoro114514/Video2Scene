# 从 RGB 视频到可编辑场景

[项目首页](../README.md) · [合成客厅案例](SHOWCASE.md) · [离线 HTML 说明](MODELING_WORKFLOW.html)

Video2Scene 的主线是本地 Pi 工作台。模型负责观察、提出布局与编写对象建模代码；宿主负责工具执行、授权范围、证据绑定、资产验证和场景版本。用户在白模阶段核对并采用布局，然后进入对象精修。

## 1. 导入与观察

导入静态室内场景的视频，说明目标。工作台记录输入哈希并采样观察帧，Pi 根据图像建立对象先验与候选关系。观察帧、相机、深度与掩码始终通过原始帧号对应。

ViPE 使用独立的密集时间序列估计相机与深度；SAM 根据目标提示生成实例掩码。工作台将两条证据支路汇合，形成对象点、空间范围和支撑关系的测量提议。视频片段的相机估计、透明面和遮挡仍可能不可靠。

## 2. 白模与人工核对

Agent 结合测量和可见图像提出白模。浏览器展示源图与场景，用户可修改位置、尺寸、类别及支撑对象，并保存版本。

“采用布局”绑定当前保存版本与允许精修的目标。后续精修继承该布局的变换、局部边界和支撑关系；改变布局后需要按新版本重新核对。人工采用是工作流中的明确步骤。

## 3. 对象作者与独立复核

每个对象获得目标专属证据、局部坐标约定和布局约束。对象作者通过 Codex CLI 编写 Blender 建模代码，构建对象资产；后端重开、渲染并检查资产。独立 critic 根据源图和渲染图提出接受或返修意见。

单对象默认最多两轮、四次作者／critic 调用。技术检查、视觉复核和场景保存分别记录；视觉接受并不代替技术验证，也不证明不可见部分的真实形状。

## 4. 持续调度与共享资源

新整屋批次默认同时维护 3 个对象任务，可选 1–4。一个对象完成后，先持久化其资产包，再按依赖与积压额度补入下一件。其他对象仍在生成时，已完成资产可以进入保存。

| 设置 | 默认／范围 | 作用 |
| --- | --- | --- |
| 对象任务 | 3／1–4 | 同时处于生成与复核流程的目标数 |
| 模型名额 | 3／1–4 | 服务内跨项目共享的对象作者／critic 调用额度 |
| Blender 执行组 | 1／1–2 | 服务内共享的构建、渲染及作者执行额度 |
| 场景保存 | 每场景 1 | 合并、验证、提交串行执行 |
| 待保存积压 | 每场景 3 | 达到额度后暂缓补入新生成任务 |

作者整个调用会保守占用一个 Blender 名额，以覆盖作者内部启动 Blender 的路径。对象并发数不等于始终同时运行的作者数，也不是加速倍数。旧单对象及分轮批次继续读取原模式。

## 5. 合并、保存与导出

独立资产包带有目标、输入和内容哈希。`save_refinement` 将合并、技术验证和提交封装为一个工具操作：读取最新获准场景，只替换目标资产，保留其他对象。检查点绑定候选和验证记录；丢失回执后可查询同一保存事务。

目标或支撑已变化时，旧资产不能直接写回。所有目标完成后，导出绑定最终保存版本的 `.blend` 与 `.glb`，并记录文件哈希。可继续在 Blender 中编辑这些几何资产。

## 6. 暂停、连接失败与恢复

- 暂停整批会停止补位和新合并；页面显示运行任务是否还在收尾。
- 单对象暂停保留已完成资产和历史，恢复时先核对任务状态、进程身份及授权。
- 主控 Pi 的瞬时连接错误最多重试 5 次，间隔为 2／4／8／16／30 秒。
- 对象 CLI 仅对日志证明尚未执行的容量拒绝增加最多两次连接尝试，等待 15／30 秒，并共享原调用超时。
- 有工具执行或结果不明时，不自动重放作者。显式恢复会保留旧失败记录并核验是否可创建新任务。

请求 ID 用于查询和幂等。浏览器刷新、状态轮询和页面重连均不应启动第二份建模任务。
